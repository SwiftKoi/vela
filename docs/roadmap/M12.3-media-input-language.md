# M12.3 — Media, input and language

**Goal.** The three surfaces a game ships that are neither its story nor its screens: **sound**, the
**input map**, and **translation** — plus the theme a skin is made of.

**Depends on.** M12.2 (audio's volume settings live in its store; the help screens display this
milestone's input map), M09 (the importer registry).

**Followed by.** M13.

## Why these three are one step

They are what is left of `the_question` after the story (M12), the images (M12), the screens
(M12.1) and the interface (M12.2): **one Opus track**, **13 translation trees** (~20,000 lines), and
the input handling behind the help screens. Three small systems rather than one large one, and each
has a clear owner in the existing specs — `SCREENS.md §11` for input, `BUILD_AND_ASSETS.md §3.1` for
the importer, `LANGUAGE.md` for the strings — so the milestone is mostly a matter of *doing* what is
already described.

It also carries the last piece of the theme question: `gui.rpy`'s 126 values are the *data* of a skin,
and M12.1 §2 decided the look is not reproduced. The values are still worth taking, because a project
that migrates keeps its palette even when it gets a new dialogue box.

## Work items

1. **Audio import**: an importer for Ogg/Opus — the one track `the_question` ships — plus WAV.
   `M09`'s item 1 named audio and did not deliver it.
2. **Audio playback**: channels (music, sound, voice), `play`/`stop`/`queue` (already in
   `LANGUAGE.md §3`), loop points, fade in and out, and mute per channel.
3. **Volumes as settings**: the store is M12.2's; the binding is this one's.
4. **The input map**: `SCREENS.md §11`'s semantic actions with per-device profiles — keyboard, mouse,
   gamepad, touch — rebindable by the player and persisted alongside the settings.
5. **Device variants**: `renpy.variant("small")`, 7 uses in the sample, which M12.1 adds to the
   screen language as a *prop* and this milestone gives a runtime meaning to.
6. **The translation catalogue**: extraction of translatable strings, a catalogue format, runtime
   switching, and the `Language(...)` action that 13 uses in the sample need. Nothing in the specs
   describes this today — it is the largest unowned surface the survey found.
7. **`tl/**` migration**: 52 files, 13 languages, in Ren'Py's format. The strings are the value; the
   format is not.
8. **The theme surface**: `gui.rpy`'s colours, sizes and spacings as a Vela theme of typed tokens
   (`SCREENS.md §5`), so a migrated project keeps its palette.
9. **`M12-migration.md`'s `_()` markers**, the last two report entries the story still produces.

## Exit criteria

- [ ] `illurock.opus` plays, loops, fades and mutes, and the volume survives a restart.
- [ ] A key can be rebound in the interface and the new binding is in force the next time the game
      runs — asserted, not clicked.
- [ ] A migrated `tl/` tree produces a catalogue that switches at runtime, with at least one language
      asserted in a test.
- [ ] `the_question` migrates with **no `_()` marker reported** and no audio file skipped.
- [ ] A migrated project's colours come from its own `gui.rpy` values, not from a default.

## Status

**Not started.** Scope recorded from `M12.1`'s survey; nothing built.

## Still open

- **Translation's format and timing.** Extraction can be done at build time or at migration time, and
  a catalogue that a translator edits needs a stable identity per string — which is the same problem
  as `RUNTIME.md §5`'s statement identity, and may want the same answer.
- **How much of Ren'Py's `tl/` is worth taking.** A tree of 20,000 lines is a real translation of a
  real game; taking it means the migrated project ships 13 languages, and *not* taking it means the
  migration reports 52 files. Neither is obviously right, and it is a policy question rather than a
  technical one.
- **Audio's boundary with M13.** Video, Live2D and particles are M13's ("rich media works"); audio is
  here because `M09` named it and a VN without music is not the same game. If M13 wants all of media,
  items 1–3 move there and only the input map and translation stay.
- **Where `variant` is decided**: in the screen language (M12.1), in the screen *pack*
  (`SCREENS.md §13`), or by the host at runtime.

## Risks

Three unrelated systems under one milestone, each with its own way of being deep — an audio mixer, a
rebinding UI, a translation pipeline. The rule that keeps it bounded is the one M12.1 used: **the
count in the sample is the scope.** One track, 13 trees, 7 variants — not the general problem.
